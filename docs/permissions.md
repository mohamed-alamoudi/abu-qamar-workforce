# المستخدمون والصلاحيات

## الأدوار

| الدور | الوصف |
|---|---|
| `ADMIN` | حساب واحد فقط بصلاحيات كاملة. لا يُعطَّل، ولا تُعدَّل صلاحياته، ولا يُنشأ غيره (قيود في قاعدة البيانات). |
| `SUPERVISOR` | مراقب. لا يملك شيئًا افتراضيًا؛ يمنحه الأدمن صلاحيات فردية من الكتالوج. |

الموظفون لا يملكون حسابات دخول.

## كتالوج الصلاحيات القابلة للمنح

المصدر الوحيد: `packages/shared/src/permissions.ts` (يُزامَن إلى جدول `permissions` عند إقلاع الخادم).

| المفتاح | المعنى |
|---|---|
| `employees.view` | عرض الموظفين والأقسام |
| `employees.create` | إضافة موظفين |
| `employees.update` | تعديل بيانات الموظفين غير المالية |
| `attendance.view` | عرض سجلات الدوام |
| `attendance.check_in` | تسجيل الحضور |
| `attendance.check_out` | تسجيل الانصراف |
| `attendance.correct` | تصحيح سجلات الدوام |
| `leaves.view` | عرض الإجازات والغياب |
| `leaves.record` | تسجيل إجازة أو غياب (بانتظار اعتماد الأدمن) |
| `reports.attendance` | عرض تقارير الدوام |
| `reports.absence` | عرض تقارير الغياب |
| `reports.financial` | عرض التقارير المالية (قراءة فقط) |
| `reports.payments` | عرض تقارير الدفعات (قراءة فقط) |
| `finance.view` | عرض المعلومات المالية (قراءة فقط) |

## ما لا يمكن منحه لمراقب أبدًا

هذه العمليات **ليست صلاحيات في الكتالوج أصلًا**، فلا توجد طريقة لمنحها — تُفرض في الخادم بفحص الدور (`@AdminOnly`):

حذف السجلات · تعديل العمليات المالية · تحضير مسودات الرواتب · اعتماد الرواتب · إغلاق فترات الرواتب ·
تسجيل دفعات الرواتب · التسويات المالية · تغيير قواعد الأجور · إدارة المستخدمين والصلاحيات ·
تغيير الإعدادات · النسخ الاحتياطي والاسترداد · مراجعة سجل التدقيق.

## طبقات الفرض

1. **الخادم (الأساس):** `SecurityGuard` على كل مسار، والافتراضي «للأدمن فقط».
2. **التحقق من المدخلات:** `PUT /users/:id/permissions` يرفض أي مفتاح خارج الكتالوج، ويرفض تعديل صلاحيات الأدمن.
3. **قاعدة البيانات:** أدمن واحد، الأدمن دائمًا نشط، سجل التدقيق للإضافة فقط.
4. **الواجهة (للتجربة فقط):** إخفاء ما لا يملكه المستخدم. ليست حاجزًا أمنيًا.

## إضافة مسار جديد (للمطورين)

```ts
@RequirePermissions('employees.view')        // كل الصلاحيات المذكورة
@RequireAnyPermission('attendance.view', 'reports.attendance') // واحدة منها
@AdminOnly()                                  // للأدمن فقط
@AnyAuthenticated()                           // أي مستخدم مسجّل
@RequireReauth()                              // + إعادة إدخال كلمة المرور
```

مسار بلا أي تعليم = للأدمن فقط.

## سجل التدقيق

كل حدث حساس يُسجَّل في `audit_logs` بالفاعل والوقت وعنوان IP والقيمة القديمة والجديدة، ضمن معاملة العملية نفسها.
الأحداث الحالية: `auth.*` (دخول، خروج، حظر، إعادة تحقق، كلمة المرور، الجلسات، المصادقة الثنائية، الإعداد)،
`user.*` (إنشاء، تعديل، تعطيل/تفعيل، صلاحيات، إعادة تعيين كلمة المرور، إلغاء الجلسات)، `settings.updated`.
الجدول محمي بـ trigger يمنع أي `UPDATE` أو `DELETE`.

## الموظفون والأقسام (المرحلة الثانية)

| العملية | من يستطيع |
|---|---|
| عرض الموظفين وتاريخ أقسامهم وسجل تغييراتهم | `employees.view` |
| إضافة موظف (دون أجر) | `employees.create` |
| تعديل الاسم والهاتف، والنقل بين الأقسام | `employees.update` |
| رؤية الأجر وتاريخه وسياساته | `finance.view` (مع `employees.view`) |
| تحديد/تغيير الأجر وسياسة الاحتساب | الأدمن فقط |
| إيقاف موظف وإعادة تفعيله | الأدمن فقط |
| إضافة/تعديل/تعطيل/حذف الأقسام | الأدمن فقط (قائمة الأقسام يقرؤها أي مستخدم مسجّل) |

- من لا يملك `finance.view` يستلم `payVisible: false` ولا تصله قيمة الأجر إطلاقًا، وتُحذف تغييرات الأجر من سجل التغييرات الذي يراه.
- إيقاف الموظف جُعل للأدمن فقط لأنه يمس استحقاقه المالي (افتراض آمن؛ يمكن فتحه لاحقًا بصلاحية مستقلة).
- المراقب الذي يضيف موظفًا لا يستطيع تحديد أجره؛ يظهر الموظف بعلامة «لم يُحدَّد الأجر» حتى يحدده الأدمن.
