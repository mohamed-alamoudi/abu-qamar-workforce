# النسخ الاحتياطي والاسترداد

## السياسة المعتمدة

| النوع | التكرار | مدة الاحتفاظ |
|---|---|---|
| يومية | كل يوم | 30 يومًا |
| أسبوعية | كل أسبوع | 3 أشهر |
| يدوية | من لوحة الأدمن | حتى الحذف |
| قبل الاسترداد | تلقائيًا قبل كل استرداد | 30 يومًا |

- النسخ مشفرة (`BACKUP_ENCRYPTION_KEY`) ومخزنة في تخزين كائنات **منفصل** عن قاعدة البيانات (`BACKUP_STORAGE_*`).
- لا نفترض أن مزوّد القاعدة يحتفظ بالنسخ لهذه المدد؛ التنفيذ بمهمة مجدولة (Render Cron Job) تستدعي `pg_dump`.
- فشل أي نسخة يولّد إشعارًا للأدمن.

## خطوات الاسترداد

1. اختيار نسخة. 2. فحص سلامة الملف (SHA-256). 3. التحقق من إصدار المخطط. 4. معاينة المحتوى.
5. نسخة أمان من البيانات الحالية. 6. إعادة إدخال كلمة مرور الأدمن. 7. إيقاف الكتابة والمزامنة.
8. الاسترداد. 9. فحص البيانات. 10. إعادة فتح النظام.

لا يُقبل رفع ملف قاعدة بيانات خارجي وتنفيذه؛ الاسترداد من نسخ أنشأها النظام نفسه وتحقق من بصمتها فقط.
الاسترداد يُختبر فعليًا على بيئة منفصلة قبل اعتماده.

## التشغيل

اضبط مفتاحًا عشوائيًا مستقلًا في `BACKUP_ENCRYPTION_KEY` واحتفظ بنسخة منه في مدير أسرار منفصل. تغييره يجعل الملفات السابقة غير قابلة للفك بالمفتاح الجديد. للتطوير اضبط `BACKUP_STORAGE_DRIVER=local` واختر `BACKUP_LOCAL_DIR` عند الحاجة. للتخزين البعيد استخدم `s3` واملأ المتغيرات الموضحة في وثائق النشر.

للتشغيل المحلي على Windows، اضبط الأوامر في `.env` بما يناسب حاوية قاعدة البيانات التي يستعملها الخادم.

```dotenv
PG_DUMP_COMMAND="docker exec -i -e PGPASSWORD abu-qamar-db-1 pg_dump"
PG_RESTORE_COMMAND="docker exec -i -e PGPASSWORD abu-qamar-db-1 pg_restore"
PG_TOOLS_HOST=localhost
PG_TOOLS_PORT=5432
```

بعد بناء الخادم، نفّذ `pnpm --filter @abu-qamar/api backup scheduled`. تشغّل المهمة المجدولة الأمر نفسه عند 01:00 UTC. أول يوم من الأسبوع في إعدادات النظام ينتج نسخة أسبوعية. تعمل بقية الأيام بنسخ يومية. يشغّل الأمر أيضًا حذف النسخ المنتهية. للحذف وحده استخدم `backup expire`.

صفحة «النسخ الاحتياطية» للأدمن تعرض نتيجة الفحص ومقارنة أعداد الصفوف. عند تأكيد الاسترداد يتحقق الخادم من إعادة المصادقة قبل بدء العمل. يبدأ وضع الصيانة قبل أخذ نسخة الأمان وتُنتظر الطلبات الجارية حتى تشمل اللقطة أحدث التغييرات. تُلغى الجلسات بعد الاسترداد الناجح. تعتمد إشارة الصيانة الحالية على تشغيل نسخة API واحدة. يمنع قفل PostgreSQL بدء مهمة نسخ أو حذف من CLI خلال الاسترداد. عند تعذر التحقق من الاسترداد يحاول الخادم الرجوع إلى نسخة الأمان. إذا تعذر الرجوع تبقى واجهة API في الصيانة إلى أن يراجع مسؤول التشغيل السجل ويتحقق من القاعدة.

للتحقق في قاعدة مؤقتة منفصلة، استخدم `pnpm --filter @abu-qamar/api backup drill <id>` في بيئة اختبار. يحتاج مستخدم PostgreSQL إلى صلاحية إنشاء قاعدة. بعد فقدان فهرس النسخ يمكن استيراد البيانات الوصفية الموقّعة عبر `backup rescan`.
