# الاختبارات

## الأنواع والأوامر

| النوع | الأمر | يحتاج | الموقع |
|---|---|---|---|
| فحص الأنواع | `pnpm typecheck` | — | كل الحزم |
| وحدة — الحزمة المشتركة | `pnpm --filter @abu-qamar/shared test` | — | `packages/shared/src/*.test.ts` (Vitest) |
| وحدة — الخادم | `pnpm --filter @abu-qamar/api test` | — | `apps/api/src/**/*.spec.ts` (Jest) |
| وحدة — الواجهة | `pnpm --filter @abu-qamar/web test` | — | `apps/web/src/**/*.test.ts` (Vitest) |
| تكامل | `pnpm test:integration` | PostgreSQL للاختبار | `tests/integration/*.int-spec.ts` (Jest + Supertest) |
| E2E | `pnpm test:e2e` | النظام مشغَّلًا + متصفح Playwright | `tests/e2e/specs` |

`pnpm test:unit` يشغّل كل اختبارات الوحدة.

## اختبارات التكامل

تشغّل الخادم الحقيقي كاملًا (الحارس الأمني، التحقق، فلاتر الأخطاء) فوق PostgreSQL حقيقية، لأن قيود EXCLUDE والـ triggers لا تُختبر بغير ذلك.

- القاعدة: `DATABASE_URL_TEST` (الحاوية `db-test` على المنفذ 5433، تخزينها في الذاكرة).
- قبل التشغيل تُطبَّق كل الـ migrations تلقائيًا، وقبل كل اختبار **تُمسح كل الجداول**.
- حماية: يرفض التشغيل إن لم يحتوِ اسم القاعدة على `test` أو إن طابق `DATABASE_URL`
  (`apps/api/test/test-database.ts`).
- الأسرار تُولَّد عشوائيًا لكل تشغيل.

### ما تغطيه المرحلة الأولى

**المصادقة (`auth.int-spec.ts`):** إعداد الأدمن الأول (رمز خاطئ، أحادي الاستخدام، طلبات متزامنة) · دخول صحيح ·
كلمة مرور خاطئة · حساب معطل · حظر مؤقت · جلسة منتهية وخاملة · تذكر الجهاز · الخروج وإلغاء الجلسات ·
تغيير كلمة المرور · CSRF و Origin · إعادة التحقق · المصادقة الثنائية ورموز الاسترداد.

**المستخدمون والصلاحيات (`users-permissions.int-spec.ts`):** منع المراقب من كل مسارات الأدمن ·
منع منح صلاحية خارج الكتالوج · إنشاء/تعطيل/تفعيل مراقب · سريان الصلاحيات فورًا · حماية حساب الأدمن ·
سجل التدقيق (المحتوى، حجب الأسرار، منع التعديل) · الإعدادات · لوحة التحكم · الإشعارات.

**الموظفون والأقسام (`employees.int-spec.ts`):** إضافة وتعديل موظف · كشف التعديل المتزامن · إيقاف وإعادة تفعيل ·
النقل بين الأقسام وتاريخه · تغيير الأجر ومنع تداخل فتراته · سياسات الاحتساب (يومي كامل/نسبي، طرق خصم الغياب الثلاث) ·
منع المساس بفترة رواتب مغلقة · صلاحيات المراقب وحجب الأجر · البحث والتصفية · سجل التغييرات · قواعد حذف/تعطيل الأقسام.

**قيود القاعدة (`database-constraints.int-spec.ts`):** تداخل الأجور والورديات والإجازات وفترات الرواتب ·
وردية بعد منتصف الليل · مفتاح منع تكرار الدفعة · منع حذف/تعديل العمليات المالية والعكس مرة واحدة ·
حماية الفترة المغلقة والترحيل · أرصدة السلف والديون.

## E2E

```bash
pnpm --filter @abu-qamar/e2e install:browsers   # مرة واحدة
pnpm dev                                         # في طرفية أخرى
E2E_ADMIN_USERNAME=... E2E_ADMIN_PASSWORD=... pnpm test:e2e
```

## ما لم يُغطَّ بعد

تُختبر وظائف الحضور والمالية والتقارير في فروعها. بعد الدمج أعد اختبارات المزامنة مع `AttendanceService` وإجراءات الواجهة الفعلية.

## اختبارات منصة التشغيل

- `pnpm lint` يفحص تطبيقَي API وWeb والحزم والاختبارات.
- يستخدم اختبار النسخ أرشيف PostgreSQL فعليًا ويجرب استرداده إلى قاعدة مؤقتة باسم عشوائي. يطابق عدد الصفوف في كل جدول ويغيّر بايتًا من الملف المشفّر لاختبار رفضه.
- على Windows مرّر `TEST_PG_DUMP_COMMAND="docker exec -i -e PGPASSWORD abu-qamar-db-test-1 pg_dump"` و`TEST_PG_RESTORE_COMMAND="docker exec -i -e PGPASSWORD abu-qamar-db-test-1 pg_restore"`، مع `TEST_PG_TOOLS_HOST=localhost` و`TEST_PG_TOOLS_PORT=5432`. يستخدم CI حاوية خدمة PostgreSQL الخاصة بالتشغيل. على جهاز يملك الأدوات الأصلية تكفي إتاحتها على PATH.
- اختبارات Playwright تستعمل قاعدة محلية مخصصة. شغّل API على 4040 والواجهة على 3040 لفرع platform، واضبط `API_URL=http://localhost:4040` أثناء بناء الواجهة و`E2E_BASE_URL=http://localhost:3040`. جهز أدمن الاختبار واضبط `E2E_ADMIN_USERNAME` و`E2E_ADMIN_PASSWORD`، ثم نفّذ `pnpm --filter @abu-qamar/e2e install:browsers` و`pnpm test:e2e`. تُنشئ السيناريوهات سجلات اختبار في القاعدة المستهدفة.
- شغّل الواجهة ببناء إنتاجي محلي لاختبار Service Worker. فعّل `E2E_BACKUPS=1` بعد تهيئة مفتاح وأدوات ومجلد النسخ في الخادم المحلي لتشغيل سيناريو النسخ من واجهة الأدمن.
